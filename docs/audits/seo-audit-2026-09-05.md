# Biolex SEO Audit — 5 September 2026

Full-site audit of `www.biolexlife.com` across eight dimensions: technical, schema,
content, sitemap, GEO/AI-search, SXO, on-page, and Google API data.

**Scope:** 314 sitemap URLs — 208 published blog posts, 90 printable detail pages,
5 category pages, 11 static/legal pages.

**Method:** live `curl` fetches against production, direct Supabase queries against
the content tables, and source inspection. Every finding below was verified on the
running site or in the code; nothing is inferred from templates alone.

---

## Verdict

The engineering is genuinely good. SSR is clean, schema is comprehensive and
correctly `@id`-linked, security headers are complete, AI crawlers are explicitly
allowed, `llms.txt` and `rsl.xml` both exist and are valid, and content metadata is
100% populated across all 208 posts (zero missing titles, descriptions, excerpts,
quick answers, FAQs, images, or categories).

Two things are holding the site back, and neither is a metadata problem.

1. **A crawl-architecture bug is orphaning 19 posts and discounting 17 pagination
   pages.** This is a contained, high-certainty bug with a small fix.
2. **The content architecture is aimed at the wrong page type.** The site publishes
   1,350-word articles for queries that Google answers with download-first
   galleries. This is a strategy decision, not a bug, and it is the ceiling on
   everything else.

The site currently ranks for none of its head terms. Some of that is a new domain
with almost no authority signals. But fixing authority will not help while the
crawl graph leaks and the page type is mismatched.

## CRITICAL

### C1. All 18 blog pagination pages self-canonicalize to `/blog`, orphaning 19 posts

`app/blog/page.tsx:18` exports a **static** `metadata` object with
`alternates: { canonical: "/blog" }`. A static export cannot vary by `searchParams`,
so every `?page=N` variant inherits the page-1 canonical.

Verified live:

```
/blog?page=3    → canonical https://www.biolexlife.com/blog   robots: index, follow
/blog?q=mandala → canonical https://www.biolexlife.com/blog   robots: index, follow
```

Google discounts the links on canonicalized-away pages, so the pagination chain
stops working as a discovery path. That matters because of a second cap:
`app/category/[slug]/page.tsx:83` fetches with `limit: 50` and the route renders no
pagination at all.

Confirmed by query — posts ranked beyond position 50 in their own category:

| Category | Posts | Beyond the 50 cap |
|---|---|---|
| home-organization | 60 | **10** |
| printable-wall-art | 59 | **9** |
| coloring-pages | 39 | 0 |
| kids-printables | 34 | 0 |
| meal-planning | 16 | 0 |

**19 posts** are reachable only through the discounted pagination chain. Live checks
confirm the mechanism: `/category/home-organization` renders exactly 50 post links,
`/blog` and `/blog?page=2` render 12 each. The category page also prints
`{posts.length} posts`, so a truncated category advertises "50 posts" as the total.

**Fix:** convert `/blog` metadata to `generateMetadata({ searchParams })` emitting a
self-referencing canonical per page; add pagination to the category route or raise
the cap above the largest category and use a real count for the label.

### C2. Three legal pages are `noindex` *and* submitted in the sitemap

`app/privacy-policy/page.tsx:11`, `app/terms-of-use/page.tsx:11`, and
`app/disclaimer/page.tsx:10` set `robots: { index: false }`. All three are in
`sitemap.xml`. Verified live:

```
privacy-policy    <meta name="robots" content="noindex">
terms-of-use      <meta name="robots" content="noindex">
disclaimer        <meta name="robots" content="noindex">
editorial-policy  <meta name="robots" content="index, follow">
```

This produces "Submitted URL marked noindex" in Search Console. It is also a trust
own-goal: these are exactly the pages quality raters and ad networks check for
legitimacy, and the sibling legal pages are already indexable, so the site is
inconsistent with itself.

**Fix:** remove the three `robots: { index: false }` lines. Two-minute change.

### C3. Page-type mismatch against the SERP

Across six head queries covering all five categories, the ranking pages were
gallery-first or roundup-first in **6 of 6** cases — Graphics Fairy, Cottage Market,
Little Gold Pixel, iMOM, 101 Planners, iHeartCraftyThings. The chore-chart winner
carries essentially no article body at all. The most text-heavy winner runs roughly
half of Biolex's per-post average, front-loaded before the payoff.

Biolex ships the opposite: 208 Article-type pages, 1,076-1,530 words, ~6 H2s each,
a table in 203 of them.

The cost is measurable on a matched pair (`adventure-awaits`):

| | `/blog/adventure-awaits-printable` | `/free-printables/adventure-awaits-wall-art` |
|---|---|---|
| HTML | 102,700 bytes | 60,556 bytes |
| Words | ~1,350 | 369 |
| Words before the download link | **~1,011** | ~0 |
| Direct PDF link | none | yes, above the fold |
| Schema | BlogPosting + FAQPage | DigitalDocument only |

A user landing on the blog post passes ~1,011 words and 49% of the page before
reaching a *link* to the download page — the PDF itself is a second page load away.

The internal link graph makes this worse. Verified live: `/category/printable-wall-art`
contains **50 links to `/blog/` and 0 to `/free-printables/`**, and the homepage
contains **0 direct printable links**. The site routes all of its internal authority
into the page type least likely to rank, and starves the one that actually holds the
download.

**Recommendation:** make `/free-printables/<slug>` the canonical target for
exact-match head queries ("free printable X", "X coloring page"). Rebuild category
pages as visual thumbnail grids pointing at printable pages. Demote the articles to
genuinely informational long-tail angles (how to frame, how to style), or fold them
in beneath the download. This is the single highest-leverage change on this list,
and also the largest.

## HIGH

### H1. Every printable page links to the same 3 related printables

`app/free-printables/[slug]/page.tsx:181` does
`all.filter(p => p.slug !== slug).slice(0, 3)` — the first three of an unsorted
global list, with no category filter. All 7 sampled detail pages showed identical
related items: *Rosette Mandala*, *Hearts Pattern*, *Star Pattern*. A grocery list
recommends three mandalas.

This wastes ~270 internal links, concentrates all printable PageRank on 3 arbitrary
files, and leaves the other 87 with only the listing page as an inbound link. The
companion-article fallback has the same flaw: 5 of 7 sampled pages link the same
nature-coloring article, including a bathroom-labels page.

### H2. Author archive caps at 100 of 208 posts while claiming completeness

`app/author/[slug]/page.tsx:63` uses `limit: 100`, no pagination. The page's own
heading reads "Everything Muhammad has written" while showing fewer than half. Beyond
the lost crawl path, that is a factual misstatement on the primary E-E-A-T page.

### H3. The "print-tested" claim is made only to machines

`CLAUDE.md` and the `Person` JSON-LD both state the author "designs and print-tests
every printable." Verified across the corpus:

```
posts matching /print-tested|i tested|we tested|i printed|tested on/ : 0 of 208
```

The claim never appears in visible body copy on any post, and there is no visible
author byline or bio inside the article body — only `<head>` metadata. This is the
site's single strongest differentiator against generic AI-generated printable blogs,
and it is invisible to readers.

Encouragingly, the raw material exists: 70 posts already cite specific paper weights
and 16 name printer brands. The specificity is there; the first-person experience
framing is not.

### H4. Zero outbound links across all 208 posts

Confirmed two ways: no post body contains `](http`, and parsing the rendered
`<article>` element for `/blog/closet-organization-printable` returns **0 off-domain
links**. The LinkedIn URL that a naive grep finds lives only in the JSON-LD block —
a reader can never see or click it.

For a site making practical claims (paper weights, child-development benefits of
coloring, grocery budget figures), citing nothing is a trust-signal failure under
current quality guidance, and it specifically suppresses Perplexity and AI Overview
citability, which favor pages that model good sourcing themselves.

### H5. Blog listing hides every post title from sighted users

`app/blog/page.tsx:184-190` applies `sr-only` to the `CardTitle` whenever a post has
a featured image — which all 12 on page 1 do. Live HTML confirms
`<h2 class="sr-only">Free Printable Nature Coloring Pages</h2>`. Cards render as an
image plus excerpt with no visible headline. This is broken UX, and hiding text that
has no visible equivalent is a pattern Google discounts.

### H6. GEO answer blocks systematically overshoot the target

`CLAUDE.md` specifies self-contained 134-167 word answer blocks per H2. Measured
across 60 H2 sections in 10 posts:

```
In the 134-167 band :  13 (22%)
Over 167 words      :  47 (78%)
Under 134 words     :   0
Average             : 197 words
```

The overshoot is structural, not random. The **final H2 before the FAQ** is the
worst offender in all 10 posts sampled, averaging **258 words** — 55% over ceiling —
because it functions as a catch-all wrap-up section. A second independent sample of
90 sections found the same pattern (20% in band, 198-word average).

Positive: 100% of sampled H2s are phrased as questions, and the visible
`Quick Answer` block averages a tight, quotable **55 words** with a correctly wired
`speakable` selector. That block is the site's best citability asset.

### H7. Cannibalization across near-duplicate clusters

`living-room-wall-art-printable` and `printable-wall-art-for-living-room` share
100% of title tokens and near-identical H2 intent (both cover best art, size over
sofa, colors, gallery wall, printing/framing), published 8 days apart. **Merge.**

Other confirmed clusters: 7 mandala posts, 7 grocery-list posts, 4 closet posts, and
a quotes cluster. In the closet cluster the differentiation is cosmetic — the
small-closet and walk-in "zones" tables teach the same zones in near-identical
wording, despite genuinely different underlying intents.

**Treatment per cluster:** merge + 301 (near-identical intent), canonicalize (keep
live, pick one internal-link target), or force real differentiation.

## MEDIUM

- **M1. Apex redirect is a 2-hop chain.** `http://biolexlife.com` → `https://biolexlife.com`
  → `https://www.biolexlife.com`. Fix in Vercel domain settings, one rule.
- **M2. All 208 posts share one identical `lastmod`** (`2026-09-03T18:59:13.294147+00:00`)
  from a bulk update. Google discounts `lastmod` it detects as uncorrelated with real
  edits. Consider a `content_updated_at` set deliberately by the publishing workflow.
  Note the *code* here is correct — `app/sitemap.ts` deliberately omits `lastmod` on
  static pages with a sound rationale, and 298 of 314 URLs do carry it.
- **M3. `getPublishedPosts({ limit: 1000 })`** in `app/sitemap.ts:49` will silently
  truncate the sitemap past 1,000 posts with no error. Add pagination or a cap alarm.
- **M4. No `ItemList` on `/blog`, `/free-printables`, or the 5 category pages.**
  Costs carousel/list rich-result eligibility on exactly the pages meant to be indexes.
- **M5. Printable pages carry `DigitalDocument` only** — no `Product`/`Offer` with
  `price: "0.00"`. Accurate (they are genuinely free) and standard for free-download
  pages. Do **not** add `AggregateRating`/`Review` without real reviews.
- **M6. `llms.txt` lists only 12 hub links** — not one of the 208 posts or 90
  printables. An LLM reading it learns the site has five pillars and nothing about
  what actually exists. Auto-generate a per-category top-N list, or ship
  `llms-full.txt` (title + quick_answer + URL for all 208 would be ~15-20k words).
- **M7. Category title tags read `"Printable Wall Art: Blog | Biolex"`**
  (`app/category/[slug]/page.tsx:43`). "Blog" wastes budget in a 60-char limit and
  describes the wrong page type. Prefer `Free Printable Wall Art | Biolex`.
- **M8. `/free-printables` renders a dead CTA section.** `siteConfig.audienceSegments`
  is `[]`, but `app/free-printables/page.tsx:204-231` renders the heading and
  "Each hub has guides, printables, and tools picked for your situation" with zero
  links behind it. Guard the section.
- **M9. Category pages are thin archive shells** — one DB sentence of unique copy
  above the grid. `content/segment-intros.ts` is an empty object. For head terms like
  "printable wall art" these are the best-matched URLs on the site.
- **M10. No IndexNow.** Cheap Bing/Yandex win for a site publishing regularly.

## LOW

- **L1.** One `seo_title` exceeds 60 chars (`weekly-cleaning-schedule-printable`, 61).
- **L2.** `BlogPosting.image` is a bare URL, not an `ImageObject` with dimensions.
  The front-end already forces `aspect-[16/9]`, so `1200x675` is safe and truthful.
- **L3.** Raw Postgres microsecond timestamps (`.294147+00:00`) pass through
  unformatted into schema and sitemap. Valid ISO 8601, cosmetic only.
- **L4.** `Organization`/`Person` `sameAs` contains one LinkedIn URL. Pinterest is
  the obvious channel for this niche and `scripts/build-pins.mjs` already exists.
- **L5.** Zero H3s in any post body — the only H3s on the site come from the rendered
  FAQ. Flattens hierarchy for scanning and citation granularity.
- **L6.** `/about` H1 is the site tagline, repeated in every page footer.
- **L7.** `/editorial-policy` (347 words) and `/affiliate-disclosure` (286 words) have
  exactly one heading each — no sectioning on pages raters actually read.
- **L8.** Homepage renders a single `<img>`: the author headshot. No product imagery.
- **L9.** `robots.txt` allows `CCBot` and `cohere-ai`, which are training-only
  crawlers that return no citation value. Minor, and arguably intentional.

## Verified as correct — do not regress

- **SSR is complete.** Raw `curl` with no JS returns full article text, headings, and
  all 12 JSON-LD blocks.
- **Schema is well-built.** `PERSON_ID`/`ORG_ID` are consistently `@id`-linked across
  every page type; no malformed JSON, no deprecated types, no missing required
  properties. Nothing would fail Rich Results Test.
- **Security headers complete** — HSTS `max-age=63072000; includeSubDomains; preload`,
  CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy.
  No `X-Powered-By` leak.
- **AI crawler access confirmed by live fetch**, not just robots.txt: GPTBot,
  ClaudeBot, PerplexityBot, and OAI-SearchBot all return `200`. No WAF challenge.
- **Sitemap is accurate** — 314 URLs, valid XML, matching the DB exactly (208 posts,
  90 printables), all-`https://www.`, no duplicates. 43 sampled URLs returned 200
  with no redirects.
- **`rsl.xml` is valid** and maximally permissive with attribution required — the
  right posture for a citation-growth strategy.
- **Printable meta descriptions are genuinely unique**, hand-written, not templated.
- **One H1 per page** across all 14 page types checked; **all images have alt text**;
  `og-default.jpg` is a valid 1200x630 JPEG.
- **Content metadata is 100% populated** across 208 posts, and `scripts/lib-dedash.mjs`
  is working — zero em/en dashes in the corpus.

## Not measured

**No Google API credentials are configured** (`~/.config/claude-seo/google-api.json`
absent, no `GOOGLE_API_KEY`), so there is **no Core Web Vitals field or lab data, no
Search Console indexation or query data, and no GA4 traffic** in this audit. Nothing
was estimated in their place. Page-weight figures above are raw HTML byte counts, not
performance measurements.

To enable: create a GCP project, enable PageSpeed Insights API + Chrome UX Report API,
create an API key, and write `{"api_key": "..."}` to `~/.config/claude-seo/google-api.json`.
Add a service account with Search Console and GA4 access for the rest.

Also not covered: rendered-viewport/visual above-the-fold testing (no Playwright run),
tap-target sizing, and per-post review of the ~190 posts outside the samples.
